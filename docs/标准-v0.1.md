# 智序前端标准 v0.1

状态：第一版规矩文档。范围仅为前端；后端约定另行定义。

## 1. 三端技术基线

| 端 | 标准 | 版本依据 |
|---|---|---|
| Web 后台 | React + TypeScript + Vite + Ant Design | Dr.life+ `apps/admin/package.json`：React 19.2.3、TypeScript 5.9.3（根 `package.json`）、Vite 7.3.0、Ant Design 6.1.3；Node 22.x、pnpm 10.28.2（根 `package.json`） |
| H5 / Telegram 小程序 | React + TypeScript + Vite + 自有移动端控件 | Web 侧沿用 Dr.life+ 的 React 19.2.3、TypeScript 5.9.3、Vite 7.3.0；移动控件不依赖桌面端组件库 |
| 手机 App | React Native + Expo | RouteFit `apps/driver/package.json`：React 19.3.0、React Native 0.88.1、Expo 58.0.23、TypeScript ~6.0.2 |

KhmerX Flutter App 保留，只接收令牌导出以对齐视觉，不在本标准仓库内重写 Flutter 控件。版本依据是只读核对结果；升级需单独记录兼容性影响。

## 2. 仓库结构

一个仓库、多个包，包之间只通过公开入口依赖：

```text
tokens/      源令牌与四端产物
ui-web/      Ant Design 主题与 Web 控件封装
ui-h5/       移动网页控件
ui-native/   React Native 控件
core/        接口、登录、多语言、表单校验、错误处理（阶段 3）
templates/   项目模板（阶段 3）
docs/        标准、对照表、迁移说明
```

第一期只实现 `tokens`、`ui-web`、`ui-h5`、`ui-native` 和展示台需要的文档；不提前实现后端能力。

## 3. 命名、目录与编号

- 包名使用小写短横线；源文件按职责命名，组件文件使用 PascalCase。
- 公共组件从包根入口导出，禁止业务页面直接引用内部实现路径。
- Web 控件编号使用 `W`，H5 使用 `H`，App 使用 `A`，后接三位数字，例如 `W001`、`H001`、`A001`。三端同一语义控件保留同一尾号。
- 组件必须明确默认、悬停/按下、聚焦、禁用、加载、错误和成功状态；不适用的状态要在文档写明。
- 键盘可达，焦点可见；表单控件有可关联的标签；正文对比度至少 4.5:1；信息不能只靠颜色表达；触控目标不小于 44px。
- 状态变化应提供文本或辅助技术可读反馈；动画支持减少动效偏好。

## 4. 弹窗、提示与抽屉

沿用 `popup-interaction-picker` 的选型结论，不在本标准重新定义一套规则：先判断是否需要用户决策、是否可撤销、内容量和是否首次使用，再选择 Toast、Tooltip、Hover Card、Popconfirm、Alert Dialog、Modal、Drawer 或 Tour。

每个浮层的实现说明必须写清：类型、位置、触发、关闭、场景；同一时间最多一个。非强制浮层应支持关闭按钮、Esc 和点击空白处中的适用项；不可逆操作使用 Alert Dialog。移动端把悬停改为点击，把侧边抽屉改为底部弹出，并保留可达的关闭方式。

## 5. 新系统与现有项目接入

新系统从 `tokens` 开始，先接入令牌，再按端接入控件；页面迁移按页面分批，不要求一次性重写。每个迁移页面须完成状态、键盘/无障碍、对比度和触控区域检查后再进入下一页。

现有项目按以下顺序接入：

1. 导入令牌产物，保留原业务行为和路由。
2. 将颜色、字号、间距、圆角和动效替换为令牌；一次只改当前页面。
3. 将页面中的基础按钮、输入、选择、开关和提示替换为对应端控件。
4. 对照表核对属性与行为，补齐缺失状态和无障碍标签。
5. 通过页面级回归后再继续下一页；不在迁移中顺手改变业务流程。

### 版本与公开仓库约束

提交内容、文档、测试数据和示例必须适合公开发布：不包含密钥、令牌、内部域名、本机路径、真实姓名、客户名或内部派单编号；不整段复制业务项目代码。依赖必须具备允许公开分发的许可证。自动检查脚本在仓库检查流程中执行。
