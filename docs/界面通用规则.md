# 界面通用规则

适用范围：网页与大屏（标准框架 zxgc-kit）、Telegram Mini App 与 H5、司机端 React Native。Apple HIG 原文面向 Apple 原生 App；下表只采用可跨平台的原则，并把平台专有要求换算为本项目规则。

出处：<https://developer.apple.com/design/human-interface-guidelines/>（访问日期：2026-11-14）。本页不复制 HIG 条文或 Apple 字体文件。

## 规则表

| 规则 | 原则的可用表述 | 网页与大屏 | Mini App 与 H5 | 司机端 | 怎么检查 |
|---|---|---|---|---|---|
| 层级 | 最重要的内容最醒目 | 页面标题、关键数值、主操作各只有一个视觉首要层级；大屏按观看距离提高字号 | 首屏先给任务和主操作，次要内容下沉 | 驾驶中只保留当前任务与安全动作 | 5秒测试：遮住说明文字，能否说出主任务和下一步 |
| 和谐 | 界面配合设备和系统形态 | 使用令牌控制颜色、圆角、材质和动效；大屏按远距阅读调整比例 | 小屏优先单列、底部操作；动效支持减少动效 | 遵循 Android 触控与系统返回习惯，不照搬 iOS 外观 | 320/390/1440/3300 宽度截图；核对令牌和动效降级 |
| 一致 | 同样的操作在哪里都一样 | 标准框架已有控件优先；返回、确认、错误反馈保持同语义 | 悬停换为点击；保持相同文案、状态和关闭方式 | 同一任务使用同一位置和反馈 | 跨三端逐项操作一次，记录文案、位置、状态是否一致 |
| 点击区域 | 原生 44pt × 44pt | 44 CSS px × 44 CSS px；桌面密集表格可缩小可视间距，但可点击热区仍不小于 32px，触控目标仍用44px | 44 CSS px；安卓触控实现按 48dp 预算 | 48dp 触控目标，关键驾驶操作不更小 | DevTools/布局测量热区，取最小宽高；键盘焦点也必须可见 |
| 正文 | 正文保持可读和足够对比 | 普通网页正文 17 CSS px = `1.0625rem`（根字号16px）；大屏不固定套17px，因观看距离和像素密度不同，使用大屏字号令牌并按实机距离测读 | 默认 17 CSS px = `1.0625rem`，允许用户放大 | React Native 用可缩放字号；安卓以 sp 为单位 | 计算正文/背景对比度，正文至少4.5:1；分别以100%和200%字号检查 |
| 颜色 | 使用系统动态颜色并支持深色 | 映射为语义颜色令牌（背景、文本、边框、状态）和 light/dark 两套值 | 同一语义令牌随主题切换，不把业务色写死 | 映射为主题令牌，跟随系统深浅设置 | 切换 light/dark；扫描硬编码颜色；测正文、图标、边框对比度 |
| 动态字号 | 支持动态字号和辅助技术 | 字号用 `rem`/相对布局；放大到 200% 不截断、不覆盖、不丢操作 | rem/相对尺寸；长文和表单允许自然换行 | 使用可缩放字体与无障碍标签 | 浏览器200%或系统大字号；检查横向滚动、截断、重叠和焦点顺序 |
| 系统组件 | 优先使用系统原生组件 | 对应为“优先用标准框架已有控件，不为单个页面新造控件”；只有契约缺失时才扩展 | 复用 H5/小程序标准控件并保持手势语义 | 复用 React Native/平台控件，不仿造 iOS 专有控件 | 新控件必须说明复用失败原因、状态、键盘/无障碍行为 |
| 反馈与引导 | 操作后即时反馈；首次使用有清晰引导 | 按钮按下、成功、错误、加载都有可见和文本/辅助技术反馈 | 点击后即时反馈，避免只用颜色；抽屉和弹层可关闭 | 关键动作给短、明确、可打断的反馈 | 逐个触发主操作，记录反馈延迟、可撤销性、关闭方式 |
| 布局 | 留白和对齐优先于装饰 | 16px 为默认最小间距令牌，内容宽度随视口；大屏按网格和观看距离扩展 | 16px 默认边距，窄屏不强制双列 | 以单列任务流为默认，避免驾驶中横向阅读 | 网格线覆盖截图；检查边距、对齐、内容是否被装饰挤压 |

## 平台专有边界

SF Pro、VoiceOver、iPhone 标签栏、iPad 双列侧边栏、Mac 菜单栏、Apple 原生组件等只在 Apple 原生界面适用。网页、H5、Telegram Mini App 和 Android 司机端采用上表的语义等价物，不伪装成 Apple 原生界面。

## 生成前指令

先读本页与 `DESIGN.md` 对应端小节；识别界面类型、观看距离、输入方式和主题；优先复用标准框架已有控件；为状态、键盘/无障碍、深色模式、动态字号和减少动效写出检查方法。

## 生成后自查

勾选 `docs/HIG-自查清单.md`。不满足的项必须列出实际读数、影响范围和是否需要另一个任务修复；不要用“看起来正常”代替测量。
